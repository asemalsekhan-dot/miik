MIIK Clean Base 1.0 RC6 — functional regression repair

Basis: RC5. Stable 0.3.5 remains untouched.

User-observed RC5 regressions addressed:
1) PLAN/CALENDAR ROOT CAUSE FIX
   - RC3/RC4 security cleanup had incorrectly changed two internal numeric cache keys from `${y}-${m}-${d}` to `${y}-${E(m)}-${d}`.
   - Those two IIFEs do not define E, so calendar/plan execution could throw ReferenceError at runtime even though node --check passed.
   - RC6 restores both internal numeric keys to `${y}-${m}-${d}`.
   - This is the concrete runtime cause targeted for: empty plan pages, empty calendar data, week/semester/day interactions failing.

2) STUDENT DATA PRINT ORIENTATION
   - Remaining legacy student-data print templates that explicitly requested A4 landscape were changed to A4 portrait.
   - Plan printing that intentionally uses landscape was NOT changed.

3) NOOR IMPORT FEEDBACK
   - On successful import, the student page is reopened first and then the success notice is shown, so the result is not immediately hidden by navigation/rerender.
   - Import parsing/storage logic itself was not rewritten.

Static checks after edits:
- 87 script tags total / 86 non-empty inline-or-external units as before.
- 0 JavaScript syntax errors in inline script blocks under node --check.
- 0 duplicate static DOM IDs.
- 0 occurrences of the erroneous `${y}-${E(m)}-${d}` cache-key pattern.
- 0 localStorage.clear().
- No data migration or new data deletion added.
- Static packaged assets copied unchanged from RC5.

Important limitation:
This repair is based on a concrete runtime root cause plus static checks. Browser interaction must verify plan/calendar restoration, Noor import feedback, and portrait student-data printing.
