MIK Clean Base 1.0 RC5 — Deep Clean Audit Candidate

Basis: RC4. Stable 0.3.5 remains untouched.

RC5 targeted work:
1) Build marker updated to clean-base-1.0-rc5.
2) Removed student names from inline JavaScript arguments in the remaining identified suggestion generations:
   - early v27 suggestion path
   - v29 v27 override
   - universalSuggestions (v27/v30 path)
   - v82 suggestion path
   - v83 studentSuggestions override
   These now use numeric data indexes + DOM onclick handlers and pass the stored name as data, not executable source text.
3) Escaped displayed student metadata in those paths.
4) Hardened the legacy v38 CSV temporary render: user CSV fields are HTML-escaped and the temporary inline openStudent(name,...) handler was removed. The function reloads immediately after import, so that temporary card did not need to be interactive.
5) No localStorage migration/clear was introduced. No feature redesign was intended.

Static checks after edits:
- 87 script tags total; 86 non-empty inline script bodies checked with node --check.
- JavaScript syntax errors: 0.
- Duplicate IDs in static DOM: 0.
- miikEditWeeklyV24 references: 0.
- Direct template patterns v27AddStudent('${...}), v82AddStudent('${...}), chooseActionStudent('${...}) in suggestion code: 0.
- Bundled static assets are byte-identical to RC4.

Important scope statement:
RC5 is still a compatibility/deep-clean candidate, not a claim that the historical single-file architecture has been rewritten from scratch. Remaining raw template expressions must be judged by context: some intentionally inject trusted HTML/CSS/assets or internal numeric/state values. Browser interaction testing is still required before replacing stable 0.3.5.
